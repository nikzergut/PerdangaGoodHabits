## Баги

### 1. Высокий приоритет: падение приложения на крайних датах

**Статус: исправлено.** Добавлены `MIN_YEAR = 1900`, `MAX_YEAR = 2100`, проверка `checked_add_signed()` в `build_days()`, валидация каждой даты и `min`/`max` у date picker. Добавлены 5 юнит-тестов.

**Файлы:** `src-tauri/src/lib.rs:124-137`, `src-tauri/src/lib.rs:164-169`, `src-tauri/src/lib.rs:33`

`build_days()` делает `anchor + Duration::days(offset)` без проверки переполнения. Через date picker можно выбрать, например, `9999-12-31`. Тогда `anchor = 9999-12-24`, а последний день окна — `10000-01-06`. `chrono` паникует, а из-за `panic = "abort"` в `Cargo.toml` завершается весь процесс.

**Предложение:** использовать `checked_add_signed()` и возвращать ошибку вместо паники; ограничить допустимый диапазон дат на бэкенде и/или в date picker.

### 2. Высокий приоритет: состояние меняется до успешной записи на диск

**Статус: исправлено.** Мутация вынесена в чистые функции `add_habit_to_store`, `delete_habit_from_store`, `toggle_day_in_store`: они работают с клоном `Store`. Команды записывают клон на диск и только после успешной записи подменяют состояние под `Mutex`. Добавлены 3 теста на неизменность исходного store.

**Файлы:** `src-tauri/src/lib.rs:199-207`, `src-tauri/src/lib.rs:220-226`, `src-tauri/src/lib.rs:248-258`

В `add_habit`, `delete_habit` и `toggle_day` `Store` сначала мутируется в памяти, и только затем вызывается `save_store_to_path(...)?`. Если запись не удалась (нет места, нет прав, сбой), команда возвращает `Err`, frontend откатывает UI, но **в памяти бэкенда изменение остаётся**. Следующий `get_board` покажет несохранённые данные, а после перезапуска они исчезнут.

**Предложение:** клонировать `Store`, мутировать клон, успешно записать его на диск и только после этого заменять состояние под `Mutex`.

### 3. Высокий приоритет: неатомарная запись и отказ запуска при битом JSON

**Статус: исправлено.** Запись идёт в `habits.json.tmp` с `sync_all()`, затем файл переименовывается в `habits.json`. При битом JSON повреждённый файл копируется в `habits.json.bak`, данные при возможности восстанавливаются из `.tmp`, иначе приложение стартует с пустым store вместо падения. Добавлены `SCHEMA_VERSION = 1`, миграция legacy-файлов и нормализация `next_id`. Добавлены 5 тестов на запись, бэкап, восстановление и миграции.

**Файлы:** `src-tauri/src/lib.rs:82-99`, `src-tauri/src/lib.rs:271-279`

`fs::write()` перезаписывает `habits.json` напрямую. При сбое можно получить усечённый файл. Тогда `load_store_from_path()` возвращает ошибку, `.setup()` падает, и приложение **не запускается вообще**.

**Предложение:**

- записывать во временный файл и делать `rename`;
- хранить backup предыдущей версии;
- при битом JSON не падать, а сделать бэкап повреждённого файла и стартовать с пустым store;
- добавить версию схемы и миграции.

### 4. Средний приоритет: гонка при навигации во время toggle

**Статус: исправлено.** Введены `isBusy()` (учитывает `pendingToggles`), `syncControls()` (блокирует навигацию/добавление/удаление, но оставляет доступными другие чекбоксы) и `generation`-счётчик. Все замены борда идут через `applyBoard()`, которая инкрементит generation и очищает отложенные toggle. Ответы от устаревших toggle игнорируются. `node --check main.js` проходит.

**Файлы:** `src/main.js:290-321`, `src/main.js:323-327`, `src/main.js:126-141`

`toggle_day` не выставляет `state.busy` — блокируется только конкретный чекбокс. Пока запрос в полёте, пользователь может нажать «Вперёд» или «Сегодня». `loadBoard()` перерисует таблицу, а ответ от старого toggle придёт уже к новым `state.habits`. При ошибке rollback может изменить не ту ячейку.

**Предложение:** блокировать навигацию, пока `pendingToggles.size > 0`; либо ввести generation counter и игнорировать устаревшие ответы; либо перезагружать борд после завершения всех ожидающих toggle.

### 5. Средний приоритет: несколько копий приложения легко потеряют данные

**Статус: исправлено.** Подключён официальный `tauri-plugin-single-instance` (зарегистрирован первым, под `#[cfg(desktop)]`). Повторный запуск завершает вторую копию и фокусирует/разворачивает окно уже работающей. Проверено запуском двух debug-процессов: остаётся ровно один процесс. Capabilities не менялись — у плагина нет JS API.

**Файлы:** `src-tauri/Cargo.toml`, `src-tauri/src/lib.rs:439`

Нет single-instance механизма и файлового лока. Два запущенных экземпляра читают один и тот же `habits.json`, и последняя запись перетирает изменения первой.

**Предложение:** добавить single-instance плагин Tauri или файловый лок и корректно завершать второй экземпляр.

### 6. Средний приоритет: добавление привычки сбрасывает навигацию на сегодня

**Статус: исправлено.** `add_habit` принимает `anchor` и `days`, как `delete_habit`, и валидирует anchor до мутации/записи. Frontend передаёт текущее окно, веб-адаптер делает то же самое. Добавлены тест на сохранение anchor в `board_from_store` и проверка в web smoke-тесте.

**Файлы:** `src-tauri/src/lib.rs:209`, `src/main.js:238-243`

`delete_habit` сохраняет текущий `anchor`, а `add_habit` всегда возвращает окно «сегодня». Если пользователь смотрит прошлую неделю и добавляет привычку, view прыгает на текущую дату.

**Предложение:** передавать `anchor` и `days` в `add_habit`, как это уже делается в `delete_habit`.

### 7. Средний приоритет: доступность календаря

**Статус: исправлено.** Кнопка получила обработчик: с клавиатуры она открывает нативный picker через `showPicker()` или фокусирует input. Input убран из таб-порядка (`tabindex="-1"`), чтобы не было дубль-стопа; у обёртки добавлен `:focus-within` с видимым outline. Кнопка связана с input через `aria-controls`.

**Файлы:** `src/index.html:29-37`, `src/main.js:338-342`

`#calendar-btn` видим и фокусируется, но не имеет обработчика — реально кликает прозрачный `input[type=date]`, наложенный поверх. Для клавиатуры это плохо: Enter/Space на кнопке ничего не делает, а сам input невидим и не показывает фокус.

**Предложение:** либо убрать кнопку и стилизовать сам input, либо добавить `showPicker()`/`focus()` и `:focus-within` на обёртке.

### 8. Низкий приоритет: слабая валидация на бэкенде

**Статус: исправлено.** Добавлен `MAX_NAME_LEN = 80` и проверка длины имени (в символах) в Rust и в веб-адаптере. `normalize_store` теперь переприсваивает нулевые и дублирующиеся id, а `next_id` всегда больше максимального. `toggle_day` принимает `anchor`/`days` и отклоняет даты вне текущего окна; диапазон 1900–2100 уже был добавлен в пункте №1. Добавлены 3 Rust-теста и проверки в web smoke-тесте.

- `maxlength="80"` есть только в HTML; `add_habit` не проверяет длину.
- `next_id` и дубликаты `id` при загрузке файла не валидируются.
- `toggle_day` принимает любую корректную дату, даже вне окна и очень далёкую.

**Предложение:** добавить серверную валидацию длины имени, нормализовать `next_id` при загрузке, проверять уникальность `id` и ограничивать диапазон дат.

### 9. Низкий приоритет: clippy и форматирование

**Статус: исправлено.** `data_file(&app.handle())` заменено на `data_file(app.handle())`, выполнен `cargo fmt`, `cargo clippy --all-targets -- -D warnings` проходит без ошибок.

- `src-tauri/src/lib.rs:272`: `data_file(&app.handle())` → `data_file(app.handle())`.
- Выполнить `cargo fmt` для `src-tauri/src/lib.rs`.

## Безопасность

1. **Статус: исправлено.** **`csp: null`** в `src-tauri/tauri.conf.json:20-22`. Сейчас XSS был бы опасным из-за `withGlobalTauri: true`: любой injected-скрипт мог бы вызывать все команды. Имена привычек экранируются через `escapeHtml()`, но лучше включить жёсткий CSP, например:
   `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; font-src 'self'`.

   Включён CSP в виде объекта: `default-src 'self'`, `script-src 'self'`, `connect-src ipc: http://ipc.localhost`, `style-src 'self' 'unsafe-inline'`, `font-src 'self'`, `img-src 'self' data:`, `object-src/base-uri/frame-src 'none'`. IPC-разрешение сохранено.
2. **Статус: исправлено.** **Внешние Google Fonts** в `src/index.html:5-10` — утечка IP/логов и зависимость от сети в десктопном офлайн-приложении. Лучше положить шрифт в `src/assets` или полностью удалить внешний запрос.

   Теги `preconnect` и stylesheet удалены; `--font` теперь использует системный сток `Arial Black / Helvetica Neue / Arial / sans-serif`.
3. **Статус: исправлено.** **`withGlobalTauri: true`** в `src-tauri/tauri.conf.json:10` — удобно, но расширяет поверхность атаки. Можно перейти на `@tauri-apps/api` и отключить глобал.

   Добавлена зависимость `@tauri-apps/api`; её `core.js` и `tslib` скопированы в `src/vendor/tauri/` сценарием `npm run sync:tauri-api`, чтобы не вводить bundler и сохранить общий `src/` для десктопа и Pages. `api.js` импортирует `invoke` из локального модуля и определяет Tauri по `window.__TAURI_INTERNALS__`, а не по `__TAURI__`. `withGlobalTauri` выключен.
4. **Статус: исправлено.** **Неиспользуемый `tauri-plugin-opener`** в `src-tauri/Cargo.toml:25` и разрешение `opener:default` в `src-tauri/capabilities/default.json:8`. Плагин не используется, зато даёт дополнительные права. Удалить.

   Зависимость, `.plugin(tauri_plugin_opener::init())` и разрешение `opener:default` удалены; `Cargo.lock` обновлён.
5. **Статус: исправлено.** **Ошибки с абсолютными путями** в сообщениях (`src-tauri/src/lib.rs:68-70`, `83`, `98`) попадают в UI. Не критично, но лучше логировать подробности, а пользователю показывать короткое сообщение.

   Добавлен `detailed_error()`: путь и системная ошибка уходят в `eprintln!`, а команда возвращает только короткое сообщение. Добавлен тест, что ошибка сохранения не содержит каталог или разделитель пути.
6. Нет **code signing**, **updater** и проверки подписи обновлений. Для распространения это обязательно.
7. `bundle.targets: "all"` в `tauri.conf.json:25-26` заставляет обычный `npm run tauri build` пытаться собрать MSI и NSIS. Без установленных WiX Toolset / NSIS сборка упадёт. Для portable-билда уже добавлен `npm run build:win`; для Windows стоит явно зафиксировать нужный target.
